## 1. 器件与引脚

74HC138 把 3 位二进制地址 `A2A1A0` 译成 8 路低有效输出，同一时刻只有一路为低，其余为高。

**使能条件**：`E1=0` 且 `E2=0` 且 `E3=1` 时才译码；否则 8 路输出全部为高。

| DIP16 引脚 | 信号名 | 方向 | 说明 |
|---|---|---|---|
| 1 | A0 | 输入 | 地址 LSB |
| 2 | A1 | 输入 | 地址 |
| 3 | A2 | 输入 | 地址 MSB |
| 4 | E1 | 输入 | 使能，低有效（丝印常写 /G2A） |
| 5 | E2 | 输入 | 使能，低有效（/G2B） |
| 6 | E3 | 输入 | 使能，高有效（G1） |
| 7 | Y7 | 输出 | 低有效 |
| 8 | GND | 地 | |
| 9~15 | Y6, Y5, Y4, Y3, Y2, Y1, Y0 | 输出 | 低有效 |
| 16 | VCC | 电源 | 5 V |

真值表（使能有效时）：

| A2 A1 A0 | 输出为低的那一路 |
|---|---|
| 0 0 0 | Y0 |
| 0 0 1 | Y1 |
| 0 1 0 | Y2 |
| 0 1 1 | Y3 |
| 1 0 0 | Y4 |
| 1 0 1 | Y5 |
| 1 1 0 | Y6 |
| 1 1 1 | Y7 |

## 2. 接线（通用器件接口板）

`.sig` 里已经按下面的顺序分配好通道，照接即可（通道号格式 `板卡:站点内资源:通道`）：

| 信号 | 仪器类型 | 通道 | 接到 74HC138 |
|---|---|---|---|
| VDD | DPS | `1:1:0` | 16 脚 VCC |
| A0 | DIO | `1:1:0` | 1 脚 |
| A1 | DIO | `1:1:1` | 2 脚 |
| A2 | DIO | `1:1:2` | 3 脚 |
| E1 | DIO | `1:1:3` | 4 脚 |
| E2 | DIO | `1:1:4` | 5 脚 |
| E3 | DIO | `1:1:5` | 6 脚 |
| Y0 | DIO | `1:1:6` | 15 脚 |
| Y1 | DIO | `1:1:7` | 14 脚 |
| Y2 | DIO | `1:1:8` | 13 脚 |
| Y3 | DIO | `1:1:9` | 12 脚 |
| Y4 | DIO | `1:1:10` | 11 脚 |
| Y5 | DIO | `1:1:11` | 10 脚 |
| Y6 | DIO | `1:1:12` | 9 脚 |
| Y7 | DIO | `1:1:13` | 7 脚 |

另外 **8 脚 GND 必须接到接口板的 GND**，否则所有 DC 项都会异常。

> 注意：DPS 和 DIO 是两套独立编号，`1:1:0` 在 DPS 里是电源通道，在 DIO 里是第一个数字通道，不冲突。

## 3. 测试项与限值

按 `HC138_v1.tmf` 的执行顺序：

| 序号 | 函数 | 测试项 | Sbin/Hbin | 限值 |
|---|---|---|---|---|
| 0 | `OSN_T` | 负向开短路 | 2 | 14 脚 −1.2 ~ −0.2 V（抽 −100 µA） |
| 1 | `OSP_T` | 正向开短路 | 3 | 14 脚 0.2 ~ 1.2 V（灌 +100 µA） |
| 2 | `IIL_T` | 输入低电平漏电流 | 4 | 6 个输入脚 −0.1 ~ 0.1 µA |
| 3 | `VOH_T` | 输出高电平 | 5 | 8 个输出脚 4.2 ~ 5.5 V（抽 1 mA） |
| 4 | `VOL_T` | 输出低电平 | 6 | 8 个输出脚 0 ~ 0.3 V（灌 1 mA） |
| 5 | `IDD_T` | 静态电源电流 | 7 | 0 ~ 80 µA |
| 6 | `FUNC_T` | 功能（11 条向量） | 8 | 全通过 |
| 7 | `SetPassBin` | 判 Pass | 1 | |

两个和 CD4511 案例不一样的地方，是本工程的重点：

- **VOH 怎么让 8 路同时为高**：138 输出低有效，正常译码时只有一路低。所以 `VOH_T` 把 `E1` 拉高关掉使能（`E2=0, E3=1`），此时 8 路全部被强制为高，一次性并测 8 路。
- **VOL 只能逐路测**：同一时刻只有一路为低，所以 `VOL_T` 用循环依次给 `A2A1A0 = 000~111`，对被选中的那一路灌 1 mA 再测电压，8 次结果拼成一个结果向量交给 TMF 判限。

## 4. 功能向量

`pattern/func.csv` 共 11 条向量：

| # | A0 A1 A2 | E1 E2 E3 | 期望 |
|---|---|---|---|
| 1~8 | 000 → 111 | 0 0 1 | 对应 Yn = L，其余 H |
| 9 | 000 | **1** 0 1 | 全部 H（E1 关断） |
| 10 | 000 | 0 **1** 1 | 全部 H（E2 关断） |
| 11 | 000 | 0 0 **0** | 全部 H（E3 关断），`stop` |

第 9~11 条专门验证三个使能脚能不能正常关断，这是 138 最容易被忽略、也最容易漏测的地方。

时序 `WFT1`：周期 10 µs，输入在 0 µs 处驱动，输出在 9 µs 处比较（138 的传输延迟只有几十 ns，余量充足）。

## 5. 操作步骤

### 5.1 打开工程

1. 启动 `C:\MINI-ATE\Starter.exe` → 登录 → 进入 ST-IDE（SCWorkbench）。
2. `File → Open Job`，选择 `C:\Users\Administrator\Downloads\ATE\HC138_v1\HC138_v1.job`。
3. 打开后检查右侧 Job 面板：ResDefs / Signal Map / Group / Timing / Pattern 五项都应该自动指向 `HC138_v1.*`，Library 是 `Test.dll`。

### 5.2 编译

工程目录里已经编好了一份 `Test.dll`，改代码后重新编译：

- IDE 里点工具栏的 Build（锤子图标），或
- 命令行：`cd C:\Users\Administrator\Downloads\ATE\HC138_v1` 然后 `make`

> **本机注意**：`C:\MINI-ATE\mingw64` 里的 `cc1plus.exe` 已损坏（一运行就段错误，编译会静默失败、不报错也不生成 dll）。所以 `Makefile` 里已经把编译器改成 `CXX = D:/mingw64/bin/g++`，实测可正常生成 `Test.dll`。如果以后重装 MINI-ATE 恢复了自带工具链，把这一行改回 `CXX = g++` 即可。

### 5.3 仿真跑一遍

1. 底部 `ST-DE Runner` 控制台输入 `run`，加载 `Test.dll`。
2. 输入 `sim` 进入仿真态，再 `sim:run 1` 执行一遍测试流程。
3. 看每条测试项的打印和 Bin 结果，确认流程跑通、没有 API 报错（仿真下 DC 数值是假的，只看流程）。

### 5.4 上机实测

1. 按第 2 节接好线，插上 74HC138，确认 GND 共地。
2. Runner 里 `run` → 执行测试 → 看 Datalog 里 7 个测试项的实测值与 Bin。
3. 全部通过最后 `SetPassBin` 置 Bin 1。

## 6. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 编译没反应、不生成 `Test.dll` 也不报错 | 自带 mingw 的 `cc1plus.exe` 段错误 | `Makefile` 用 `CXX = D:/mingw64/bin/g++` |
| 打开工程就提示找不到 `D:\MINI-ATE\...` | 案例工程里路径写死 D 盘 | 本工程已全部改成 `C:\MINI-ATE`；导入别人的工程要同步改 `.job`、`Makefile`、`.cproject` |
| 控制台一直刷 `connecting..` | Runner 后端没起来（路径不对/被占用） | 确认 `C:\MINI-ATE\runner\runner.exe` 存在，重启 IDE |
| 所有 DC 项读数离谱 | GND 没接、DPS 没接、接线错位 | 先跑 OSN/OSP，正常应落在 −1.2~−0.2 V / 0.2~1.2 V |
| FUNC 全 fail，DC 全过 | 向量列顺序与 `.sig` 顺序不一致 | 向量列必须严格按 `.sig` 里 14 个信号的顺序排列 |
